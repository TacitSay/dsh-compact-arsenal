# dsh-compact-arsenal

按轮次压缩 DSH 会话历史，保留用户原话与每轮结尾的答复，把中间的执行过程压成一段记录。

[![npm](https://img.shields.io/npm/v/dsh-compact-arsenal)](https://www.npmjs.com/package/dsh-compact-arsenal)
[![license](https://img.shields.io/npm/l/dsh-compact-arsenal)](LICENSE)

---

## 它做什么

DSH 会话的历史越积越长。这个插件在上下文压力升高时，把**旧轮次的执行过程**压缩成一段文字，替换掉原来的长内容。

一轮对话在会话里长这样：

```
用户：      "把 X 改成 Y"                      ← 不动
助手：      [思考] [工具调用]                   ┐
工具：      <命令输出>                          │ 压成一段
助手：      [思考] [工具调用]                   │
工具：      <命令输出>                          ┘
助手：      "改好了，改了 3 行"                  ← 不动
```

**只有中间那段被压缩。** 用户说的话和每轮最后的答复都保留原文。

## 快速开始

三种装法，按你手上有什么选一种。

### 一、从 npm 装（最省事）

```sh
dsh plugin --profile <你的 profile> add dsh-compact-arsenal
```

`<你的 profile>` 换成实际的 profile 名：桌面版通常是 `desktop`，`dsh web` 通常是 `web`。不确定就看你 `~/.dsh/profiles/` 下有哪些目录。

> ⚠️ **npm 上的版本落后于仓库。** 截至编写本 README，npm 最新为 `0.11.0`，而仓库已到 `0.17.2`。中间包含轮次压缩、批量调用、注入块判定等多项修复。想要当前功能，用下面两种方式。

### 二、从 GitHub 源码装（跟到最新）

```sh
dsh plugin --profile <你的 profile> add github:TacitSay/dsh-compact-arsenal
```

pnpm 会拉取仓库并构建。**这一步需要本机有 git 和网络访问 GitHub。**

### 三、本地 clone 后链入（开发用，改完重启即生效）

```sh
git clone https://github.com/TacitSay/dsh-compact-arsenal.git
dsh plugin --profile <你的 profile> add <clone 下来的绝对路径>
```

或者手动改 profile 的 `package.json`：

```json
{
  "dependencies": {
    "dsh-compact-arsenal": "link:C:/path/to/dsh-compact-arsenal"
  }
}
```

`link:` 形式下，**改完代码只要重启 DSH 就生效**，不用重装、不用发版。适合想自己改的人。

> 装好后改完代码，用 `node scripts/deploy.mjs` 部署并验证——它会导入部署后的入口，确认真的能加载。手工拷文件漏过一个就会导致插件静默加载失败（复盘见 `docs/postmortem-injected-blocks.md`）。

### 装完之后

重启 DSH，左栏出现「上下文压缩」图标。

**所有板块默认关闭**，装上不改变任何行为。打开面板，开启「轮次压缩」，选一个压缩模型即可。

## 压缩时发生了什么

### 触发

```
每轮对话开始前（agent/pre-step）
  → 读取当前上下文占用 / 窗口大小
  → 达到轮次压缩的触发阈值（默认 0.7）才启动
  → 否则本轮什么都不做
```

### 挑选轮次

```
把所有「用户指令 → 下一条用户指令」切成区间
  ↓
排除：最近 keepLast 轮（默认 2 轮）——那是当前工作区
排除：中间内容小于 minChars 的轮次（默认 2000 字符）
排除：已经压缩过的（检查点带标记，跳过）
  ↓
剩下的按原顺序，从最旧的开始
```

### 送给模型的内容

每一轮的过程记录，加上它末尾的答复作为参考：

```
---#1---
[ASSISTANT] [thinking] 需要先确认文件在哪
[ASSISTANT] [call read] {"path":"lib/policy.js"}
[RESULT] 文件内容……
[ASSISTANT] [thinking] 明白了，需要加一个常量
[ASSISTANT] [call edit] {"path":"…","old":"…","new":"…"}
[RESULT] done

[最终回复] 以下是这一轮结束时我给出的答复，它不会参与压缩，仅用于让你理解结果：
加好了，在 lib/policy.js 里新增了 SHORT_MARKER。
---#2---
……
```

**`[最终回复]` 的作用**：让模型的摘要与真实结论对齐。不带上它，摘要只能猜过程落在哪里，容易和表面上保留的答复矛盾。

提示词里明确要求：**结论应与 `[最终回复]` 一致，但不要照抄原文**。

### 模型返回什么

```json
[
  {"i":1,"s":"read lib/policy.js，新增 SHORT_MARKER 常量"},
  {"i":2,"s":"……"}
]
```

严格 JSON 数组，一条对应一轮。

> 解析器容忍：被散文包裹、跳过某项（该项不压缩，留待下次）、多返回项（忽略多余）。JSON 被截断时整批失败，记日志后继续下一批。

### 替换

每一轮的任务区间被替换成**一个**检查点：

```
替换前： user → a1 → tool1 → a2 → tool2 → a3
替换后： user → [检查点] → a3
```

- `a3`（结尾答复）位置不变，原文保留；
- `a1/tool1/a2/tool2` 从表面移除，但**日志里仍完整保留**，可回查；
- 检查点是一个 `user/message`，带 `[compact-arsenal turn summary]` 前缀。

**为什么检查点必须是 `user/message`**：DSH 日志有两条规则——

```
规则 1：整段替换必须引用全部被遮蔽的节点（sourceEventSeqs）
规则 2：assistant/message 禁止携带 sourceEventSeqs
```

两条互斥，所以 `assistant/message` 无法替换多节点区间。`user/message` 是唯一合法的载体。

### 分批

一轮的过程可能几十万字符。插件按字符预算分批，一批一次模型调用：

```
maxInputChars（默认按窗口推导，见下）内装尽可能多的轮次
                    ↓
每批一次模型调用 → 返回这批的摘要数组
```

**不是一轮一次调用。** 实测单轮平均约 21,000 字符，默认预算可装十余轮。

## 参数

| 参数 | 含义 | 默认 |
|---|---|---|
| 触发阈值 | 上下文占用比例达到多少才启动 | `0.7` |
| 不动最近 | 最近 N 轮不压缩 | `2` |
| 最小体积 | 单轮中间小于此值不压（字符） | `2000` |
| 占原文 | 摘要占原文的比例上限，**留空 = 不限** | 空 |
| 时间预算 | 一次触发最多跑多久（毫秒） | `600000`（10 分钟） |
| 单次输入上限 | 一批装多少字符，**留空 = 按窗口推导** | 空 |
| 输出上限 | 一批最多返回多少 token，**留空 = 按窗口推导** | 空 |

**留空的两项会自动推导**：

```
输入预算 = 窗口 token × 55%        （按 1 token ≈ 1.5 字符估算）
输出预算 = 窗口 token × 25%        （上限 200,000）
```

1M 窗口 → 输入约 825,000 字符、输出约 200,000 token。

**超时由输出预算推导**（`maxTokens / 40 + 60` 秒），不单独暴露——固定超时和可变输出量配对会失配。

## 面板

左栏「上下文压缩」：

- **轮次压缩**：开关、阈值、模型、提示词；
- **总压缩**：委托给 DSH 自带的压缩后端，只能调参数；
- **压缩留存**：是否写盘、归档目录、「打开目录」按钮、运行日志路径；
- **状态行**：本次压缩了多少轮、省下多少字符、失败几次及原因；
- **版本徽章 + 检查更新**。

改参数后 500 毫秒自动保存并热重载，不需要重启。

## 留存与日志

每一轮压缩都会写一份归档：

```
archive/<对话名>--<会话id>/turn--model--<时间>--seq<编号>.md
```

内容包含：原文字符数、改写后字符数、节省比例、模型要点、改写后内容、**完整原文**（含 `[最终回复]`）。

文件名以对话名开头，时间戳在中间——按名称排序即按时间排序，便于对比每次压缩的程度。

运行日志在 `logs/compact-arsenal.log`，记录每次触发、每批结果、每次失败的原因。

## 实测结果

54 次轮次压缩的归档统计：

```
原文合计     1,180,938 字符
改写后合计      19,898 字符
比例               1.7%
```

单轮分布（最大与最小值）：

```
62,886 → 818   (1.3%)
55,066 → 597   (1.1%)
48,105 → 516   (1.1%)
 6,710 → 215   (3.2%)
 6,447 → 409   (6.3%)
```

**这些数字说明的是压缩比例，不是成本节省。** 见下一节。

> 数字随使用增长；归档目录里的每份文件都记着自己的原文与改写字符数，可随时复核。

## 关于「省不省钱」

**这个插件不保证省钱，README 也不做这个宣称。**

原因是压缩本身有成本：

```
一次压缩 = 一次模型调用（输入是全部待压内容，输出是摘要）
```

而收益是**之后的对话**变短。两者能否相抵，取决于：

| 条件 | 结果 |
|---|---|
| 压缩后还继续聊很多轮 | 省下的输入可能超过压缩成本 |
| 压缩后很快结束会话 | 净亏损 |
| 窗口 1M、压力才 50% 就压 | 大概率亏损——还不需要腾空间 |
| 压力 90%、不压就装不下 | 压缩是必需的，不是优化 |

**所以触发阈值不该调低。** 默认 0.7 是「接近需要」而非「可以开始」。

## 已知限制

**首尾假设可能不成立。** 早期版本对思考/工具输出做头尾截断，假设「信息在两端」。这个假设对日志类输出成立，对「关键信息恰好在中段」的输出不成立。这部分功能已移除，但如果你调大 `minChars` 后仍觉得某些轮次压得太狠，可以把「占原文」设一个比例。

**摘要质量取决于模型。** 提示词要求保留命令、路径、报错原文、关键数值，但模型不保证全部照做。归档里存了完整原文，可随时核对。

**压缩后无法还原。** 表面上的内容被替换了。归档保存了原文，但没有「撤销」按钮。

**一次压缩可能是几分钟。** 大批量时模型需要逐 token 生成，实测吞吐约 105 token/秒。10 万 token 的输出约需 16 分钟。

## 配置示例

直接写 profile 的 `cordis.patch.yml`：

```yaml
- id: compact-arsenal
  name: dsh-compact-arsenal
  config:
    enabled: true
    archiveEnabled: true
    turns:
      enabled: true
      pressureRatio: 0.7
      keepLast: 2
      minChars: 2000
      summaryRatio: null      # 留空 = 不限制摘要长度
      maxInputChars: null     # 留空 = 按窗口推导
      maxTokens: null         # 留空 = 按窗口推导
      maxPassMs: 600000
      provider: ''            # 留空 = 跟随当前会话
      model: ''
    total:
      enabled: false
      pressureRatio: 0.85
      retainTurns: 2
```

## 开发

```sh
node --test test/*.test.mjs   # 116 个测试
node scripts/deploy.mjs       # 同步到安装目录并验证可加载
```

零运行时依赖，无构建步骤。

| 文件 | 职责 |
|---|---|
| `index.js` | 触发、挑选、分批、替换、路由 |
| `client.js` | 面板（React，无构建） |
| `lib/turns.js` | 区间切分、transcript、幂等识别 |
| `lib/summarize.js` | 模型调用、批量 JSON 解析、超时 |
| `lib/policy.js` | 文本测量与截断 |
| `lib/archive.js` | 归档写入 |
| `lib/log.js` | 运行日志 |

`scripts/deploy.mjs` 在同步后会**实际 import 一次部署副本**。「文件同步」和「能加载」是两个问题，只有后者决定图标是否出现。
